# AI_Hues · 开源项目「Hues」评分维度（设计稿）

**产品引用：** 本稿与 [`PRD-AI_Hues-v1-ZH-product.md`](./PRD-AI_Hues-v1-ZH-product.md) §2.1 / [`PRD-AI_Hues-v1-EN-product.md`](./PRD-AI_Hues-v1-EN-product.md) §2.1 一致；Demo 文章与 `project.html` 六维条与之对齐。

**目标：** 用 **一套稳定、可解释、可演进** 的维度替代「只看 Star」，并与 **色环隐喻** 对齐（认知层）；底层仍用 **可审计的量化指标**（数据层）。

**与文章的关系：** 每篇「项目特写」在正文里呈现 **Hues 快照**：六维 0–100 + 一句人话解读；**真分**上线后由数据管线替换当前 Demo 的 **启发式占位**。

## 一、为什么用「双层」：色环（认知）+ 六维（审计）

| 层级 | 作用 | 说明 |
|------|------|------|
| **色环层（Hue / Sat / …）** | 扫一眼 **领域、健康度、风险感** | 适合 UI：徽章、条带、雷达外圈标签；**不直接当唯一真相** |
| **审计层（六维 0–100）** | 决策时 **可点开看依据** | 与 PRD 中 Spectrum / 数据源一致，可对接 GitHub、OSV、CI、包注册表等 |

上线时：**审计层算分 → 映射成色环通道**；Demo 阶段可 **六维先用占位算法**，色环只做 **静态示意**。

## 二、推荐 P0：**六维评分（0–100）** — 建议就用这六根轴

与附件 PRD 中的 **DOCS / SEC / COM / MTN / TST / PERF** 对齐，产品对外可包装成 **Hues 六维**（中英文并列，避免纯缩写）。

| 维度键 | 英文名（UI） | 中文名 | 主要含义 | 典型信号（示例，非穷尽） |
|--------|--------------|--------|----------|----------------------------|
| **DOCS** | Docs & Onboarding | 文档与上手 | README 完整度、示例、变更日志、官网文档 | README 长度/结构、has wiki、site 链接 |
| **SEC** | Safety & Supply chain | 安全与供应链 | 漏洞、依赖风险、许可证清晰度 | OSV、Dependabot、LICENSE、安全公告 |
| **COM** | Community Health | 社区健康 | 贡献者多样性、讨论、Issue/PR 吞吐 | contributors、issue 关闭时间、discussions |
| **MTN** | Maintenance & Momentum | 维护与活力 | 是否「还活着」、发布节奏、近期提交 | last commit、release 频率、commit 曲线 |
| **TST** | Tests & CI | 测试与 CI | 自动化测试与集成可见度 | GitHub Actions、badge、默认分支保护 |
| **PERF** | Performance & Footprint | 性能与体量 | 运行时/包体/资源敏感场景 | 二进制大小、benchmark、issue 标签、领域惯例 |

**为何不用「纯 Star」当一维？** Star 已作为 **动量/流行** 的弱信号并入 **MTN / COM** 的辅助特征，而不是单独一维主分，避免与产品 Slogan 打架。

## 三、与「色环六通道」的映射（展示用）

用于 **Chromatic Map / 光谱条** 的直觉（与 PRD 术语一致时可微调文案）：

| 色环通道 | 建议主映射（展示） | 辅助 |
|----------|-------------------|------|
| **Hue（色相）** | **领域**（由语言 + topics + 人工类目规则得到） | 非 0–100，用 **离散标签**（如 `web` / `ml` / `data`） |
| **Saturation（饱和度）** | **COM** 社区活力 | 高饱和 = 社区活跃 |
| **Luminance（亮度）** | **DOCS + TST** 的合成（或二选一作主亮度） | 表示「看得懂、信得过」 |
| **Temperature（色温）** | **MTN** | 暖 = 稳定 LTS 感；冷 = 快速迭代 |
| **Opacity（不透明度）** | **SEC** | 不透明 = 安全态势更清晰 |
| **Gradient（渐变/组合）** | **Blend 预留** | 多仓组合契合度；单仓详情页可先 **隐藏或写「N/A」** |

**无障碍：** 色块永远配 **数字 + 文字标签**（WCAG 要求）。

## 四、文章里怎么写「更好」

1. **开篇**：一句话 **适合谁 / 解决什么问题**（比复述 GitHub description 更进一步）。  
2. **Hues 快照**：六维表 + **「演示分」免责声明** + 每项 **1 句人话**（为何是这个区间）。  
3. **选用建议**：**When to use / When not to**（非资深读者友好）。  
4. **行动链接**：README、Releases、Security、以及本站 **`/p/{slug}`**（未来）。  
5. **合规**：转载/元数据 **来源与时间**。
