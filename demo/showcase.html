✨ 核心功能

🎙️ 多源音频接入

支持 Zoom/Teams/腾讯会议录屏文件、本地录音、实时麦克风输入。 自动检测音频格式，无需手动转换。

👤 发言人识别

基于声纹特征的说话人分割。自动标记 "发言人 A"、"发言人 B"， 支持后期人工标注姓名。

📝 智能摘要

提取会议要点、行动项、决策记录。支持自定义模板导出为 Markdown/PDF。

🔒 企业级安全

纯本地部署，数据不出内网。支持 LDAP/SSO 集成，细粒度权限控制。

🚀 实现过程

2023-03
项目启动
公司内部需求：每周 20+ 场会议需要记录，现有云转录服务存在隐私顾虑。 决定基于 whisper.cpp 自研离线方案。
2023-05
技术验证
对比多个 whisper 实现：whisper.cpp 在 CPU 上的推理速度最快， 且 C++ 核心易于封装成 Python 服务。选定 base 模型平衡精度与速度。
2023-08
MVP 上线
内部团队试用。发现问题：长音频需要分段处理、说话人切换检测不准。 引入 WebRTC VAD 进行语音活动检测。
2023-12
开源发布
整理代码、编写文档、开源到 GitHub。一周内获得 500+ Stars， 收到多个外部公司的部署咨询。
2024-至今
企业级迭代
增加 SSO、审计日志、集群部署支持。服务客户扩展到 50+ 企业， 包括金融、法律、咨询等对隐私要求严格的行业。

⚠️ 遇到的挑战 & 解决方案

  • 🔥
    长音频内存占用
    原本直接加载整段音频导致 OOM。改为流式分段处理， 使用滑动窗口 + 上下文拼接，内存占用降低 80%。
  • 🎯
    说话人切换检测
    whisper.cpp 原生不支持说话人分割。集成 pyannote.audio 进行声纹聚类， 在转录后处理阶段对齐时间戳。
  • 🌍
    中英文混合场景
    使用 large-v3 模型 + 语言检测自动切换。对于固定中英夹杂的场景 （如技术会议），训练了领域适配的 prompt。
  • ⚡
    高并发处理
    单机性能有限。引入 Celery + Redis 任务队列，支持多 worker 并行处理。 提供进度回调 API，前端可实时展示转录进度。

💡 关键洞察

为什么选择 whisper.cpp 而不是云端 API？

不只是隐私考量。长期使用成本对比：处理 10 万小时音频， 云端 API 费用约 $50,000，而自研方案硬件成本仅 $3,000（一台中高端服务器）。 对于高频场景，本地部署的经济优势巨大。

模型选择的权衡

我们测试了所有模型大小。最终选定 base 作为默认，small 作为高精度选项： base 在常见会议场景准确率已达 95%+，而 small 的额外 2-3% 提升带来的 3 倍计算成本不划算。 用户可按场景选择。
